# 運用方針（再生数を伸ばすためのルール）

目的は再生数とフォロワーを増やすこと。TikTokはフォロワー1,000人前後でTikTok Shopアフィリエイトに申請でき（条件はアプリで要確認）、YouTubeは登録者500人などでショッピングアフィリエイトに参加できる。報酬はその先。

## アカウント
- TikTok @minmi_581 / YouTube「みん」。ジャンルは「一人暮らしのキッチン・食まわりの便利グッズ」
- 顔出し・声出しなし。Buffer経由で自動投稿（1日2本、11:45 と 19:30）

## 数字の目安（YouTubeショート）
- スワイプされずに見られた割合：60%以上で合格、70%以上でバズ圏内
- 視聴維持率：70〜80%で合格、90%超でバズ圏内
- 保存とシェアが特に効く
- 比較用の基準：ジャンル変更前のTikTok投稿は1本300〜800再生、平均視聴3〜10秒（output/metrics.md）

## 冒頭（スルーされないための逆算）2026-11-14〜
- 0秒：1コマ目から冒頭の文字を全部見せる（演出なし。自動）
- 0〜1秒：結論・得られる結果を数字つきで言い切る（疑問形だけにしない）
- 1〜3秒：sub に「続きを見たくなる一言」（例：3つ目が一番使える、2つ目はやりがち）
- 途中：上に 1/3・2/3 の進み具合バー（自動）。声は1.3倍速で全体15秒前後
- 最後：声で「保存して、もう一回1つ目から見てね」（自動）でループさせる
- 冒頭の型を JSON の hook_type に書く：result（結果）/ loss（損得）/ regret（後悔）/ question（問いかけ）。metrics.md の「冒頭の型ごとの平均」で比べ、勝った型を増やす
- 目標：TikTok平均視聴 5秒 → 8秒

## 内容の割合（2026-11-14〜）
- 知識系 7 ：商品紹介 3。知識系でフォロワーを集め、TikTok Shopの申請が近づいたら商品紹介を本物の商品画像（楽天APIなど）に切り替える
- 知識系の柱は「日本ではあまり教えてくれない知識」（海外では常識の台所ルール、保存の科学、やりがちなNG）
- 知識系は必ず事実確認する。公的機関（農林水産省、消費者庁、厚生労働省、USDA、FDA、大学の研究、論文）で裏が取れたものだけ。JSONの "sources" に出典URLと要点を書き、caption に「参考：〇〇」を1行入れる
- 体の効果・病気の予防・ダイエット効果は言わない。数字は出典どおりに（盛らない）
- 投稿順は config.json の "order" で決める（先頭から順に予約。書いていない番号は後ろ）。新しい台本を足したら order にも知識系と商品紹介が交互になるように入れる
- JSON に "kind": "knowledge" か "product" を書く。冒頭の型に surprise（意外な事実）も追加

## 台本のルール
1. 冒頭3秒で結論か得られるものを言う。疑問形の問いかけ＋数字（「1日3回」「5分」「半分」）
   - 冒頭の小さい一文には季節の言葉（寒い日・冬・年末など）を入れる（2026-11-13〜）
2. タイトルの頭に検索される言葉を置く（例：「一人暮らし 洗い物」）。予告した内容をそのまま出す
3. 1本＝1テーマ・3アイテム・13秒前後。1枚2.5秒程度
4. 最後は「保存して、あとで見返してね」で保存を促す
5. ハッシュタグは関連の強いものを3〜5個。YouTubeは #shorts を付ける（自動）
6. 型を固定しすぎない：「3選」「やめてよかった」「before/after」「〇〇な人向け」「失敗談」を混ぜる
7. 商品名・ブランド名・効果の断定（「必ず」「絶対」）は書かない。医療・健康効果は書かない

## 写真
- Wikimedia Commons の CC0／パブリックドメイン／CC BY のみ（CC BY-SA は使わない）。CC BY は説明文に作者名を自動で入れる
- 古い広告・肖像画・人の顔のアップ・ブランドロゴが目立つ写真は使わない。作り直す
- 動画ができたら全スライドを目で確認し、合わない写真の回は config.json の skip に入れて投稿しない

## 注意（YouTubeの量産コンテンツ対策）
- テンプレの使い回しだけだと「量産・再利用コンテンツ」と判断されるおそれがある。台本の中身（知っていると得する一言、比較、失敗談）で毎回違う価値を出す
- 2026-11-14からナレーション（VOICEVOX:春日部つむぎ）と自作BGMが自動で入る。読み上げ文はスライドの文字から自動で作る。言い回しを変えたい時は各スライドに "say" を書く（例：冒頭だけ話し言葉にする）
- 今後の改善候補：商品写真への置き換え

## 改善の進め方

- 一度に変えるのは1か所だけ（冒頭の一文、テンポ、写真の雰囲気など）。変えた内容は docs/changelog.md に書く
